# lecture-agent

Агент, который записывает пары, расшифровывает их локально и делает конспекты через Claude API.
Пользователь: магистрант. Группа, подгруппа и семестр заданы в `schedule.yaml`, он локальный
и в репозиторий не попадает. Оттуда же берётся, какие пары очные, а какие дистанционные.
Время в проекте всегда московское.

Этот файл собран в чате на claude.ai, где проект и писался. Истории той переписки у тебя нет,
здесь её выжимка: что уже сделано, почему сделано именно так и обо что легко споткнуться.

## Как запускать

Обычный режим у пользователя это ярлык «Агент пар» на рабочем столе, терминал не нужен.
Ярлык сделан один раз командой `python make_shortcut.py` и ведёт на `pythonw.exe launch.pyw`.

```
pip install -r requirements.txt
python make_shortcut.py     # ярлык на рабочем столе (--remove чтобы убрать)
python agent.py ui          # то же самое из терминала
python agent.py timetable   # расписание в терминале (-w на неделю)
python agent.py schedule    # сам пишет очные пары микрофоном, ярлыка для него нет
python agent.py record      # разовая запись микрофоном
python agent.py process f   # обработать готовый файл (m4a, mp3, webm, .txt)
python agent.py merge       # склеить пару, записанную кусками (--apply чтобы правда склеить)
python agent.py notes       # доделать конспекты, где есть только расшифровка (--apply)
python agent.py devices     # список микрофонов
```

## Из чего состоит

- `agent.py` - всё приложение одним файлом: запись, расшифровка, конспект, расписание, HTTP-сервер.
- `launch.pyw` - запуск без терминала: журнал, единственный экземпляр, остановка, окна с ошибками.
- `make_shortcut.py` - создаёт ярлык на рабочем столе через PowerShell и COM.
- `schedule.yaml` - расписание группы: обе подгруппы, даты в формате вуза, ссылки на занятия.
  В git не попадает, он в `.gitignore`. В репозитории лежит `schedule.example.yaml` без ссылок.
- `config.yaml` - настройки: модель Whisper, модель Claude, порт, запас времени вокруг пары.
- `web/index.html` - весь интерфейс одним файлом, без сборки и зависимостей.
- `extension/` - расширение Chrome (MV3) для записи звука конкретной вкладки.

## Как это работает вместе

1. `python agent.py ui` поднимает `ThreadingHTTPServer` на `127.0.0.1:8756` и открывает браузер.
2. Страница опрашивает `/api/state` раз в 2 секунды: текущая пара, состояние записи, прогресс.
3. Очную пару пишет микрофон (`sounddevice` -> FLAC). Дистанционную пишет расширение:
   `chrome.tabCapture` в offscreen-документе -> MediaRecorder -> куски webm по 15 секунд
   уходят POST-ом на `/chunk`, сервер дописывает их в один файл.
4. `/finish` кладёт задание в очередь `start_worker()`. Воркер один, работает по очереди,
   чтобы расшифровка предыдущей пары не мешала записи следующей.
5. `process_session` -> `transcribe` (faster-whisper локально) -> `summarize` (Claude API, стрим).
   Результат: `audio.*`, `transcript.txt`, `notes.md` в папке занятия.
6. Пару могли писать в несколько заходов: Zoom на бесплатном аккаунте рвёт встречу через
   30 минут. Тогда в папке занятия лежат `audio.webm`, `audio2.webm`, `audio3.webm`,
   у каждого куска своя расшифровка `part-N.txt`, а `parts.json` хранит, когда начался
   каждый кусок и когда кончается пара. `transcript.txt` склеивается из кусков со сквозными
   метками времени, и конспект делается один на пару, когда она кончилась по расписанию.

## Решения, которые лучше не переигрывать без причины

- **Один воркер на обработку.** Пары идут подряд с перерывом 10 минут, а расшифровка 90 минут
  звука на CPU занимает дольше. Параллелить нельзя: Whisper съест CPU и запись начнёт рваться.
- **Куски webm пишутся на диск сразу.** Если браузер закроется посреди пары, записанное уцелеет.
  При этом расширение держит полную копию в памяти и, если агент отвалился, сохраняет файл
  в Загрузки. Это осознанное дублирование, оно уже спасало в тестах.
- **Номер занятия считается из дат, а не хранится.** `meta["order"]` в `load_schedule` собирает
  все даты по каждой паре (предмет + вид), номер это позиция даты в списке. Поэтому перенос
  занятия правится только в `schedule.yaml`.
- **Проверка дней недели при загрузке расписания.** Если дата не совпадает с днём недели,
  агент падает с понятным сообщением. Это поймало бы опечатку при переносе расписания с фото.
- **Время везде московское через aware datetime.** `schedule_tz()` берёт `zoneinfo`, а если
  `tzdata` нет (Windows), откатывается на фиксированный UTC+3: Москва без перехода на лето.
- **Часы браузера сверяются с часами сервера.** В `open_session` время начала записи из
  расширения принимается только если расходится с серверным меньше чем на 10 минут.
- **Ярлык останавливает агента файлом, а не `taskkill`.** `launch.pyw` кладёт `.launcher/stop`,
  фоновый поток внутри агента видит его и зовёт `_thread.interrupt_main()`. Получается ровно
  тот же `KeyboardInterrupt`, что и от Ctrl+C, а значит срабатывает штатное завершение:
  куски записи дописываются, очередь расшифровки доделывается. Убийство процесса это потеряло бы.
- **Куски одной пары узнаются по расписанию, а не по паузе между записями.** `pair_session_dir`
  отдаёт одну и ту же папку всем записям, которые попали в окно одной пары. Пауза между
  обрывками Zoom около минуты, а между разными парами десять, но окно пары надёжнее любого
  порога. Запись вне расписания живёт по-старому: каждая в своей папке.
- **Метки сдвигаются по реальному времени начала куска, а не по длине предыдущего.** Минута,
  пока пересоздавали встречу, остаётся видна в нумерации, плюс в расшифровке стоит пометка
  о перерыве. Иначе метки разошлись бы с часами пары, и модель склеила бы мысль через разрыв.
- **Ложный старт это запись короче минуты** (`FALSE_START_SECONDS`). Такой кусок выкидывается
  вместе с файлом и не сбивает отсчёт. Порог взят по живым данным: ложные старты были
  в 1 и 11 секунд, самый короткий настоящий обрывок 6:56.
- **Конспект по кускам откладывается до конца пары** (`waiting_for_parts`). Иначе каждый обрыв
  связи стоил бы лишнего запроса к модели, а конспект переписывался бы трижды за пару.
- **Второй клик по ярлыку не поднимает второго агента.** `launch.pyw` смотрит на `.launcher/agent.pid`
  (жив ли процесс) и на занятость порта, и вместо запуска показывает окно с выбором. Два агента
  на один порт всё равно не встанут, а два Whisper сразу отняли бы процессор у записи.

## Подводные камни

- **YAML съедает время без кавычек.** `start: 10:45` превращается в число 645 (это YAML 1.1,
  шестидесятеричная запись). `parse_time` понимает и число, и строку, но в файлах время
  пишется в кавычках.
- **`tabCapture` глушит вкладку.** Захват забирает звук себе, поэтому в `offscreen.js` поток
  возвращается в колонки через `AudioContext`. Уберёшь эту строчку - пользователь перестанет
  слышать лекцию.
- **`tabCapture` требует жеста пользователя.** `getMediaStreamId` вызывается в обработчике
  клика в попапе, для активной вкладки. Для другой вкладки Chrome может отказать, там есть
  понятное сообщение.
- **Пути с кириллицей.** Папки называются по предмету, поэтому файлы в `faster-whisper`
  передаются как открытый файловый объект, а не строкой пути.
- **Под `pythonw.exe` нет ни консоли, ни `sys.stdout`.** `print()` в таком процессе тихо
  пропадает, а `sys.stderr.write` падает с `AttributeError`. Поэтому `launch.pyw` первым делом
  перенаправляет оба потока в `.launcher/agent.log`, а сообщать пользователю что-либо может
  только окном через `MessageBoxW`. Если добавляешь вывод в агента, помни: увидят его в журнале.
- **Порт освобождается раньше, чем процесс завершается.** В `run_server` сначала
  `server_close()`, и только потом `wait_jobs()`, который может ждать расшифровку ещё час.
  Поэтому `launch.pyw` проверяет не порт, а живость процесса, и даёт ему пару секунд запаса.
- **Кнопки-ссылки на странице это `<a class="act">`, а не `<button>`.** Поэтому правила
  в стилях написаны парами `button.act, a.act`. Раньше были только `button.act`, и зелёная
  «Войти» на деле рисовалась обычной подчёркнутой ссылкой, пока это не увидели в браузере.
- **Фоновые процессы в моей среде не переживали конец команды.** Сервер и тест запускались
  в одном вызове. У тебя такого ограничения нет.

## Что уже проверено

Логика расписания (развёртка дат, чётные и нечётные недели, нумерация, пересечения),
запись в FLAC, склейка webm и его декодирование, весь HTTP API, защита от выхода за папку
с записями, разбор Markdown в интерфейсе с экранированием, аварийные сценарии расширения
(агент недоступен, вкладку закрыли, повторная остановка).

Запуск ярлыком проверен вживую на Windows 11: агент поднимается без окна консоли, страница
открывается, журнал пишется, повторный клик не создаёт второго агента, остановка через ярлык
проходит штатно за полторы секунды и убирает за собой pid-файл.

Не проверено вживую: настоящий микрофон, скачивание моделей Whisper и вызов Claude API
(в среде сборки не было ни звука, ни доступа к huggingface), а также внешний вид страницы,
потому что браузера там тоже не было. Первым делом стоит прогнать короткую реальную запись.

## Открытые хвосты

- Ссылка на лекцию по ПАА с ЧПУ выглядит обрезанной, но вуз рассылает её ровно такой.
  На случай, если Zoom по ней спросит код, он записан в `schedule.yaml` в поле `passcode`.
  Ни ссылки, ни коды сюда не выписывай: этот файл публичный.
- У пар бывают поля `passcode`, `backup_link`, `backup_passcode`, все они видны в карточке
  пары рядом с «Войти». Запасная ссылка пока есть только у ПиРСИО.
- Ярлык поднимает только `ui`. Режим `schedule`, который сам пишет очные пары микрофоном,
  по-прежнему запускается из терминала. Второго ярлыка для него нет осознанно: у `schedule`
  нет страницы, и в фоне без окна он работал бы совсем вслепую.
- **Конспекты идут через OpenRouter**, ключ задан, проверено вживую на настоящем запросе.
  Провайдер выбирается в `config.yaml`, поле `summary.provider`, вариантов четыре:
  `openrouter`, `claude_cli`, `gemini`, `anthropic`.
- **Только бесплатные модели, это требование пользователя.** `openrouter_free_only: true`
  заставляет `ensure_free_model` перед каждым запросом сверяться с прайс-листом OpenRouter
  и отказываться от платной модели. Не отключай без прямой просьбы.
- **Gemini API закрыт по региону.** С рабочим ключом он отвечает
  `User location is not supported for the API use`, и это не лечится настройками.
  Проверка доступности с машины пользователя: OpenRouter, Mistral и GigaChat отвечают,
  а Gemini, Groq и `api.anthropic.com` напрямую недоступны. При этом `claude` CLI
  до Anthropic достукивается, он ходит своим путём, но его токен протух и нужен `claude login`.
- **Связь с OpenRouter рвётся примерно через раз.** Рукопожатие TLS отваливается по таймауту,
  следующая попытка проходит. Поэтому запросы идут через `open_with_retry`, который повторяет
  только обрывы связи и не трогает ответы сервера, даже ошибочные. Это не перестраховка,
  срабатывает регулярно.
- Страница отдаётся только на `127.0.0.1`. Чтобы открывать с телефона, нужно менять адрес
  в `ThreadingHTTPServer` на `0.0.0.0`, и это осмысленно только в домашней сети.
